# Param Service
Param Service (подсистема системных параметров) в OpenHarmony представляет собой централизованный клиент-серверный механизм на базе демона init, который управляет конфигурацией ОС в режиме реального времени через систему «ключ-значение». Он обеспечивает глобальное хранение настроек, безопасный межпроцессный доступ к ним с учетом AccessTokenID и прав DAC/MAC, а также поддерживает подписку на события изменения параметров.
Команды `param set` и `param get` обращаются к сервису параметров, который в обычной системе работает внутри init.
## Без родного ядра
Поскольку на тестовом стенде отсутствует init, разработано временное [решение](https://github.com/Harmony-Oneir/oneir/tree/main/non-native-kernel/src/param_service), которое заменяет оригинальный сервис.
Для сборки запустите команду `./make.sh param_service` в контейнере. Это соберет альтернативу Param Service и утилиту `param`.

Результат сборки находится по пути `out/oneir/startup/init/`:

| Файл | Назначение |
|---|---|
| `oneir_param_service` |Сервис системных параметров вместо встроенного в init: создаёт общую память с параметрами, принимает запросы на изменение через сокет |
| `param` | Консольный клиент из семейства `begetctl`: `param get`, `param set`, `param ls`, `param wait`, `param watch` |
| `libbegetutil.z.so` | Основная клиентская библиотека init: API системных параметров (`GetParameter`, `SetParameter`, `WaitParameter`, `system::GetParameter` и др.), управление сервисами. Чтение идёт напрямую из общей памяти, запись через сокет к серверу параметров |
| `libbeget_proxy.z.so` | Дополнение к `libbegetutil` с зависимостью от IPC/samgr: подписка на изменения параметров через системную способность `param_watcher`. Вынесено отдельно, чтобы базовая библиотека не тянула IPC |
| `libsystemparam.z.so` | Интерфейс системных параметров для прикладного уровня (JS/NAPI или NDK-обёртка над `libbegetutil`), через который приложения читают и пишут параметры |


## Param Watcher
Системные параметры в OHOS — это общее хранилище пар «имя → значение». Читать и писать их можно напрямую: значения лежат в разделяемой памяти, это быстро и никакой службы не требует.
А вот подписаться на изменение параметра напрямую нельзя — нужен посредник, который будет помнить, кто чем интересуется, и рассылать уведомления. Это и есть `param_watcher`. Клиент вызывает `WatchParameter("имя", callback)`, служба запоминает подписку, и когда значение меняется, дёргает обратный вызов через IPC. Param Watcher — это важная часть минимальной системы. На него полагаются остальные сервисы, например Render Service. RS делает десять попыток обратиться к `param_watcher` и завершает работу в случае отсутствия PW в системе. Собирается `param_watcher` все той же командой `./make.sh param_service`. Результат сборки лежит по пути `/out/oneir/startup/init/libparam_watcher.z.so`.

После запуска системы, Init ожидает файл `system/etc/init/param_watcher.cfg` для запуска. Запускается через `sa_main` из профиля [`/system/profile/param_watcher.json`](https://github.com/Harmony-Oneir/oneir/blob/main/profile/param_watcher.json).

## Виды параметров

Поведение параметра определяется его именем:

| Префикс | Поведение |
|---|---|
| `const.*` | Устанавливается один раз за загрузку. Повторные значения, в том числе из файлов параметров, загруженных позже, игнорируются |
| `persist.*` | Сохраняется в `/data` и восстанавливается при следующей загрузке |
| остальные | Живут только до перезагрузки |

При загрузке init читает значения по умолчанию из файлов `.para` в каталогах `etc/param` всех слоёв конфигурации: сначала системного (`/system/etc/param`), затем платы (`/vendor/etc/param`, через ссылку `/chipset`). Значения платы загружаются позже и переопределяют системные (кроме `const.*`). Права доступа к параметрам (кто может читать и изменять) задаются файлами `.para.dac`.

## Постоянные параметры (persist.*)

Init делит постоянные параметры на **публичные** и **приватные**. Признак — имя параметра: в `param_persistadp.c` (`IsPublicParam`) есть жёсткий список префиксов (`persist.wifi`, `persist.time`, `persist.update`, `persist.sys.usb.config`, `persist.init.trace.enabled` и др.). Параметр публичный, если его имя начинается с одного из них; все остальные, в том числе параметры, придуманные для продукта (например, `persist.oneir.*`), приватные.

| Вид | Файл | Когда загружается |
|---|---|---|
| Публичные | `/data/service/el1/startup/parameters/public_persist_parameters` | Командой `load_persist_params` в задании `pre-init` штатного `init.cfg`, сразу после монтирования `/data` (`mount_fstab_sp`) |
| Приватные | `/data/service/el1/public/startup/parameters/private_persist_parameters` | Командой `load_private_persist_params` в задании `post-fs` штатного `init.cfg` |

При загрузке публичных параметров приватные пропускаются (в журнале `persist.oneir.developermode is private, ignore`). Пока загрузка соответствующего вида не завершилась, init запрещает сохранять новые значения: `param set` для такого параметра срабатывает, но значение не переживёт перезагрузку, а в журнале появляется `cannot save persist param before load`. Новые значения сохраняются в файл не мгновенно, а с небольшой задержкой, поэтому перезагружать систему нужно командой `reboot`, а не выключением.

Служебные файлы init хранит в `/data/service/el1/public/startup/` (`persist_param_fixed` и подкаталог `parameters/` для приватных параметров). Штатно этот каталог создаёт не `init.cfg`, а в минимальной системе его нет, и init при каждой загрузке выдаёт `create file /data/service/el1/public/startup/persist_param_fixed fail error 2`. Каталог создаётся в задании `post-fs-data` конфига платы (`init.x86_64_oneir.cfg` и `init.x86_64_oneir_usb.cfg`):

```json
{
    "name" : "post-fs-data",
    "cmds" : [
        "mkdir /data/service/el1/public/startup 0755 root root",
        "mkdir /data/service/el1/public/startup/parameters 0755 root root"
    ]
}
```

Вставить создание каталога между монтированием `/data` и `load_persist_params` из конфига платы нельзя: они идут подряд в одном задании `pre-init`, а команды платы init дописывает в конец задания. Но каталог лежит в `/data` и сохраняется между загрузками, поэтому достаточно создать его один раз: на первой загрузке после изменения он создаётся, со следующей init находит его.

**Известная проблема:** приватные постоянные параметры пока не восстанавливаются после перезагрузки: значение записывается в `private_persist_parameters`, но загрузка `load_private_persist_params` не завершается, и init продолжает сообщать `cannot save persist param before load`. Публичные параметры (например, `persist.wifi.*`) сохраняются и восстанавливаются.

Проверка:

```sh
param set persist.wifi.oneir_test 1          # публичный параметр
sync; reboot
param get persist.wifi.oneir_test            # 1
```
