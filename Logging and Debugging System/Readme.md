# HiLog
HiLog (OpenHarmony Logging Framework) — это штатная подсистема логирования в OpenHarmony. Она используется как в C/C++ (Native API), так и в ArkTS для записи, фильтрации и анализа системных и пользовательских логов.
По своей роли HiLog является аналогом Android Logcat или Linux journalctl, но имеет строгую структуру с разделением по доменам безопасности и типам данных.

## Ключевые концепции HiLog
1. **Domain**: 32-битное шестнадцатеричное число, обозначающее модуль или подсистему. Пример:
   * `0xD001400` — логи графической подсистемы.
   * Пользовательские приложения обычно используют диапазон `0x0000–0xFFFF` или назначенный `DOMAIN`.
2. **Tag**: Строка, обозначающая конкретный класс или файл.
3. **Log Level**:
   * **DEBUG** — отладочная информация.
   * **INFO** — информационные сообщения о ходе выполнения.
   * **WARN** — предупреждения, не блокирующие работу.
   * **ERROR** — ошибки выполнения.
   * **FATAL** — критические сбои, приводящие к остановке процесса.
  
Архитектура HiLog построена по классической клиент-серверной модели. 
### Серверная часть (hilogd)

`hilogd` (HiLog Daemon) — это системный фоновый сервис, запущенный в ОС OpenHarmony.

### Инструменты чтения (hilog CLI)
Утилита, которая запускается в консоли и является клиентом hilogd. Она подключается к демону hilogd через сокет `/dev/unix/socket`.

### Сборка hilog
Для сборки hilog используйте следующую команду в контейнере:
```
./make.sh hilog
```
Результат сборки находится по пути `out/oneir/hiviewdfx/hilog`:
| Файл | Что это | Нужен для запуска? |
|---|---|---|
| `hilogd` | демон журнала: принимает записи от процессов через сокеты и хранит их в кольцевом буфере | да, запускается до остальных, чтобы логи не терялись |
| `hilog` | консольная утилита для чтения журнала из `hilogd`, фильтрации по тегам и уровням и управления буфером | для диагностики |
| `libhilog.so` | клиентская библиотека: `HILOG_INFO`, `HILOG_ERROR` и т.п., через неё пишут в журнал все компоненты | да, почти всем процессам |
| `libhilog_rust.dylib.so` | Rust-обёртка над `libhilog` для компонентов на Rust | только для Rust-компонентов |
| `libsandboxlog.so` | облегчённый вариант клиента для процессов в песочнице, где нет полного доступа к `hilogd` | обычно нет, только если его тянут зависимости |


# HiView

hiview — центральная служба диагностики (DFX) в OpenHarmony. Если hilogd собирает текстовые логи, то hiview собирает и обрабатывает структурированные системные события и следит за сбоями. Он запускается как отдельный процесс `/system/bin/hiview` по `hiview.cfg` и регистрируется в samgr как системный сервис (SA 1201).

### Что он делает?
| Функция | Роль |
| --- | --- |
| Приём системных событий (HiSysEvent) | компоненты (ATM, samgr, ability и др.) через библиотеку hisysevent отправляют события вида «право выдано», «сервис упал», «база повреждена» в сокет hiview. Он их принимает, проверяет по описаниям событий и сохраняет в свою базу | 
| Учёт сбоев (FaultLogger) | вместе с faultloggerd собирает падения нативных процессов (CppCrash), JS-сбои и зависания приложений (AppFreeze), сохраняет журналы сбоев со стеком |
| Сбор метрик | периодически снимает загрузку CPU, память, ввод-вывод, статистику использования |
| Подписки и выгрузка | раздаёт события подписчикам (в том числе приложениям через HiAppEvent), упаковывает и экспортирует журналы |
