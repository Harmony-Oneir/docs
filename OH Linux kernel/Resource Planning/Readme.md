# Введение
Подсистема планирования ресурсов (`foundation/resourceschedule`) представляет собой централизованный диспетчер операционной системы, который в реальном времени управляет распределением процессорного времени, оперативной памяти и энергии между приложениями и системными сервисами. Анализируя действия пользователя и текущий жизненный цикл ПО, подсистема координирует работу специализированных модулей (планировщика приоритетов `ressched`, менеджера памяти `memmgr`, контроллера производительности `soc_perf` и др.) и задействует механизм контрольных групп (`cgroup`) для изоляции процессов, назначения им динамических приоритетов и оптимизации общего энергопотребления устройства.

# Процессы

| Процесс | SA ID | Компоненты и назначение |
| --- | --- | --- |
| `resource_schedule_service` | 1901 (планировщик), 1903 (фоновые задачи), 1904 (отложенные задачи), 1906 (частоты soc_perf), 1907 (статистика), 1914 (режим ожидания) | `resource_schedule_service`, `background_task_mgr`, `work_scheduler`, `soc_perf`, `device_usage_statistics`, `device_standby` |
| `resource_schedule_executor` | 1918 | `resource_schedule_service` (исполнитель решений планировщика) |
| `memmgrservice` | 1909 | `memmgr` |
| `concurrent_task_service` | 1912 | `qos_manager` |

`ffrt` и `frame_aware_sched` — библиотеки без собственных системных способностей. `soc_perf` (SA 1906) работает внутри процесса `resource_schedule_service`, поэтому без планировщика его не запустить.

# Компоненты

| Компонент | Назначение |
| --- | --- |
| `resource_schedule_service` | Центральный планировщик. По событиям (приложение на переднем плане, экран выключен, запуск игры и т.п.) переносит процессы между группами `foreground`, `background`, `top-app`, `system-background`, меняет приоритеты и частоты, замораживает фоновые приложения (`freezer`) |
| `memmgr` | Менеджер памяти: следит за давлением на память, сжимает или выгружает память фоновых приложений (`zram`, `zswapd`), завершает приложения при нехватке памяти по их весу (`memory.app_score`) |
| `background_task_mgr` | Правила фоновой работы приложений: длительные задачи, проигрывание звука и т.д. |
| `work_scheduler` | Отложенные задачи приложений по условиям (зарядка, сеть и т.п.) |
| `device_usage_statistics` | Статистика использования приложений |
| `device_standby` | Глубокий режим ожидания: ограничение сети, таймеров и задач при долгом простое |
| `soc_perf` | Управление частотами процессора и графики по сценариям |
| `qos_manager` | Приоритеты потоков (QoS); ими пользуется `ffrt` |

# Зависимости

Все зависимости компонентов подсистемы входят в продукт `oneir` (полный стандартный набор из 352 компонентов). Поэтому проверки `defined(global_parts_info.<компонент>)` в `BUILD.gn` считают, что окна, звук, Bluetooth и прочее в продукте есть, и включают связанный с ними код; лишнее выключается флагами компонентов.

| Компонент | Вес | Основные зависимости |
| --- | --- | --- |
| `qos_manager` | Лёгкий | Базовые (`ipc`, `samgr`, `safwk`), `frame_aware_sched`, `ability_runtime` |
| `soc_perf` | Лёгкий | Базовые, `selinux_adapter`, `libxml2` |
| `resource_schedule_service` | Тяжёлый | Окна, звук, Bluetooth, ввод, питание, учётные записи, приложения, пакеты, CES, сеть; большая часть выключается флагами |
| `memmgr` | Средний | Пакеты, приложения, фоновые задачи, учётные записи, CES |
| `background_task_mgr`, `work_scheduler`, `device_usage_statistics`, `device_standby` | Очень тяжёлые | Интерфейс, уведомления, базы данных, время, батарея, температура, датчики, звонки; полностью ориентированы на приложения |

# Порядок переноса

1. `qos_manager` — собственный процесс, полезен сразу;
2. `resource_schedule_service` с минимальными флагами: ядро планировщика, `soc_perf`, исполнитель и модуль групп cgroup (`cgroup_sched`);
3. `memmgr`;
4. остальные.
