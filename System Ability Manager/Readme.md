# System Ability Manager (samgr) — реестр системных сервисов
Samgr — это "телефонная книга" системы. Он хранит соответствие «номер SA → binder-объект сервиса». По смыслу это аналог servicemanager в Android. Samgr нужен только для одного: помочь найти собеседника. 

## Почему нельзя обойтись без samgr
Дело в том, как binder устроен внутри.

Номера в binder — личные, а не общие. Когда процесс получает ссылку на чужой объект, ядро выдаёт ему номер, например 5. Но этот номер имеет смысл только для этого процесса. У соседа тот же процесс может быть под номером 12, а под номером 5 у него вообще что-то другое. Нельзя просто договориться, потому что общих номеров нет.

Получить номер можно только от того, у кого он уже есть. Ссылки на объекты передаются только внутри binder-сообщений. Отсюда проблема курицы и яйца: чтобы получить первую ссылку, нужно отправить сообщение, а чтобы отправить сообщение, нужна ссылка.

Номер 0 решает эту проблему. Ядро гарантирует, что у каждого процесса номер 0 всегда ведёт к context manager. Это единственный номер, который известен заранее и одинаков для всех. С него всё начинается: позвонили по нулю, попросили сервис, получили свой личный номер для общения, дальше говорите напрямую.

# Сборка samgr

Для сборки запустите следующую команду внутри контейнера:
```
./make.sh samgr
```
Результат сборки находится по пути `out/oneir/systemabilitymgr/samgr/`:

| Файл | Что это | Нужен для запуска? |
| --- | --- | --- |
| samgr | Исполняемый файл реестра: становится context manager binder (handle 0) и хранит таблицу «номер SA → объект» | да, запускается первым |
| libsamgr_proxy.z.so | Клиентская библиотека: GetSystemAbility, AddSystemAbility и т.п. Через неё к samgr обращаются sa_main, samgr_client и сервисы | да, клиентам |
| libsamgr_common.z.so | Общий код samgr и клиентов, в первую очередь разбор профилей SA | да, samgr и sa_main |
| libsamgr.dylib.so | Rust-обёртка над клиентом samgr. Суффикс .dylib.so OpenHarmony даёт разделяемым библиотекам на Rust | только если что-то на Rust |
